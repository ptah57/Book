# **Глава 17. Настройка MPLS L3VPN.** 

## **Что такое MPLS и зачем он нужен?** 

**MPLS (Multiprotocol Label Switching) - это технология, которая
сочетает скорость коммутации второго уровня с гибкостью маршрутизации
третьего уровня.**

**Простая аналогия: Представьте, что IP-маршрутизация - это обычная
почта, где каждое письмо (пакет) индивидуально обрабатывается на каждой
станции (роутере). MPLS - это экспресс-доставка с заранее проставленными
штрих-кодами (метками), где посылки быстро пересылаются по заранее
подготовленным маршрутам.**

**Где находятся метки MPLS?**

**Метка MPLS размещается между заголовком Layer 2 (Ethernet) и Layer 3
(IP):**

**\[ Ethernet Header \| MPLS Label \| IP Header \| Data \]**

**Формат MPLS метки (32 бита):**

**- 20 бит - значение метки**

**- 3 бита - приоритет (QoS)**

**- 1 бит - индикатор стека меток**

**- 8 бит - TTL**

### Преимущества MPLS: 

**- Высокая скорость передачи**

**- Traffic Engineering**

**- Поддержка VPN**

**- Качество обслуживания (QoS)**

**Роль OSPF в MPLS-сетях**

**OSPF (Open Shortest Path First) - это протокол внутреннего шлюза
(IGP), который в MPLS-сетях выполняет критически важную функцию:
обеспечивает транспортную связность между роутерами провайдера.**

**Аналогия: Если MPLS - это скоростная железная дорога, то OSPF - это
карта, которая показывает, как связаны между собой станции (роутеры).**

**Почему OSPF обязателен в MPLS?**

**1. Для LDP (Label Distribution Protocol) - OSPF обеспечивает
связность, необходимую для распространения MPLS-меток**

**2. Для BGP-сессий - MP-BGP между PE-роутерами требует IP-связности
между loopback-адресами**

**3. Для отказоустойчивости - быстрая реконвергенция при отказах
каналов**

**Loopback-адреса - это виртуальные интерфейсы, которые всегда активны.
В MPLS-сетях они используются как:**

**- Источники для BGP-сессий**

**- Идентификаторы роутеров (Router ID)**

**- Транспортные адреса для LDP**

**BGP: eBGP и MP-BGP**

**eBGP (External BGP)**

**Используется для обмена маршрутами между разными автономными системами
(AS). В нашей архитектуре, показанной на Рисунке 17-1, eBGP работает
между:**

**- PE1 (AS 65500) и CE1 (AS 65505)**

**- PE2 (AS 65500) и CE2 (AS 65505)**

**Особенности eBGP:**

**- TTL = 1 (по умолчанию)**

**- Требует прямого соединения**

**- Изменяет атрибуты при передаче маршрутов**

**MP-BGP (Multiprotocol BGP)**

**Это расширение BGP, которое поддерживает различные адресные семейства,
включая VPNv4 . Именно MP-BGP делает возможными MPLS L3VPN.**

**Ключевые концепции MP-BGP:**

**Route Distinguisher (RD) - делает маршруты уникальными:**

**- Формат: ASN:number или IP:number**

**- Пример: 65500:100**

**- Назначение: отличать одинаковые IP-префиксы разных клиентов**

**Route Target (RT) - управляет импортом/экспортом маршрутов:**

**- Export: какие маршруты отправлять в VPN**

**- Import: какие маршруты принимать в VPN**

**- Пример: route-target import/export 65500:100**

**VPNv4 адреса - это комбинация RD + IPv4 префикс:**

**- RD:65500:100 + 172.16.1.0/24 = уникальный VPNv4 маршрут**

### Архитектура MPLS L3VPN 

**Роли роутеров:**

**- CE (Customer Edge) - клиентский роутер**

**- PE (Provider Edge) - граничный роутер провайдера**

**- P (Provider) - внутренний роутер провайдера**

**Data Plane (передача данных):**

**CE1 → PE1 → P-роутер → PE2 → CE2**

**eBGP MPLS/LDP MP-BGP eBGP**

**Control Plane (обмен маршрутами):**

**1. CE1 анонсирует 172.16.1.0/24 через eBGP на PE1**

**2. PE1 добавляет RD и RT, создает VPNv4 маршрут**

**3. Через MP-BGP маршрут передается на PE2**

**4. PE2 удаляет RD, проверяет RT и импортирует в VRF**

**5. Через eBGP маршрут передается на CE2**

### VRF (Virtual Routing and Forwarding) 

**VRF создает виртуальные таблицы маршрутизации для каждого клиента,
обеспечивая:**

**- Изоляцию - клиенты не видят друг друга**

**- Переиспользование адресов - разные клиенты могут использовать
одинаковые IP-сети**

**- Безопасность - разделение трафика**

**Резюме**

**MPLS L3VPN - это мощная технология, которая использует:**

**- OSPF для транспортной связности**

**- LDP для распределения MPLS-меток**

**- MP-BGP для обмена VPN-маршрутами**

**- VRF для изоляции клиентов**

**В следующем разделе мы настроим полнофункциональную MPLS L3VPN сеть,
чтобы закрепить эти концепции на практике.**

## **Цель работы.**

Согласно схеме на Рисунке 17-1 необходимо настроить L3VPN на базе
технологии MPLS между локальными сетями офисов географически
рспределенного предприятия. Конечным результатом настройки является
появление связности между сетями удаленных офисов, подключенными по
технологии VRF ( с изоляцией трафика ) на различных маршрутизаторах сети
(то есть объединение VRF на разных маршрутизаторах через
MPLS-транспорт). При этом должна быть обеспечена передача сервисных
MPLS-меток для сервиса L3VPN посредством MP-BGP и передача транспортных
меток для достижения nexthop-адресов полученных BGP-маршрутов.

3\. Настроить OSPF для динамической маршрутизации в транспортной сети
