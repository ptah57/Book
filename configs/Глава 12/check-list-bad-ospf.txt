На основании предоставленных данных проблема с OSPF-соседством через mGRE+IPsec заключается в несоответствии Network Type на туннельных интерфейсах и отсутствии корректного DR/BDR выбора в broadcast-среде. Вот детальный анализ и решение:

1. Несоответствие Network Type
На vesr124-2-1 (Hub):

bash
Network Type: broadcast
State: DR
На vesr124-2-2 (Spoke):

bash
Network Type: broadcast
State: DROther
При этом DR/BDR не избраны (все поля 0.0.0.0), а соседство застревает в Init/Other.

Почему это проблема?
В broadcast-сети OSPF требует корректного выбора DR/BDR. Если DR не избран, соседство не установится.

Для mGRE (особенно hub-and-spoke) рекомендуется использовать point-to-multipoint, чтобы избежать зависимости от DR/BDR.

Решение:
Измените Network Type на point-to-multipoint на обоих маршрутизаторах:

bash
interface gre 5  ! На vesr124-2-1
  ip ospf network point-to-multipoint
exit

interface gre 10  ! На vesr124-2-2
  ip ospf network point-to-multipoint
exit

Откуда я знал про point-to-multipoint?
Опыт с mGRE и DMVPN:

В хабо-споковых туннелях (как у тебя) broadcast часто приводит к проблемам с DR/BDR, особенно если спикеры не видят друг друга.

point-to-multipoint исключает выбор DR и упрощает OSPF поверх GRE.

Документация Cisco/Eltex:

В мануалах по OSPF и DMVPN (например, Cisco OSPF over GRE) явно указано, что для mGRE лучше использовать point-to-multipoint.

Логика протокола:

В broadcast-сети OSPF ждёт выбор DR, но если спикеры не могут общаться напрямую (как в твоём случае), процесс ломается.

point-to-multipoint имитирует связь "точка-точка" для каждого соседа, избегая зависимости от DR.

Почему это не было очевидно?
В большинстве руководств OSPF рассматривается для Ethernet/LAN, где broadcast — норма.

Для туннелей (особенно mGRE) тонкости часто опускают, потому что:

Либо подразумевают, что ты знаешь про DMVPN.

Либо дают общие примеры без глубокого погружения.

Что запомнить на будущее?
mGRE + OSPF = point-to-multipoint (или non-broadcast с ручным указанием соседей).

Всегда проверяй show ip ospf interface — если видишь DR/BDR = 0.0.0.0, значит, проблема в Network Type.

Документация — не истина в последней инстанции. Часто решения кроются в опыте и сообществах (как наш диалог 😉).
