Глава 16. Управление резервированием.

Что такое протокол VRRP
VRRP (Virtual Router Redundancy Protocol) — сетевой протокол, разработанный для повышения доступности и избыточности маршрутизаторов. Позволяет нескольким маршрутизаторам работать как логическое устройство, совместно используя виртуальный IP-адрес и MAC-адрес.  
Протокол существует в нескольких версиях:  
VRRPv2 — поддерживает только IPv4, описан в RFC 3768.
VRRPv3 — расширенная версия, поддерживает IPv4 и IPv6, описана в RFC 5798. outsourcer.kz
•	Принцип работы
Маршрутизаторы объединяются в один виртуальный маршрутизатор. Все маршрутизаторы в группе имеют общий виртуальный IP-адрес (VIP) и общий номер группы (VRID). В VRRP MAC-адрес автоматически генерируется на основе номера группы VRRP. Используемый формат MAC-адреса: 0000.5e00.01xx, где xx — номер группы VRRP в шестнадцатеричном виде. 
В любой момент времени только один из физических маршрутизаторов выполняет маршрутизацию трафика (VRRP Master). Все остальные переходят в состояние резерва (VRRP Backup).  
При отказе главного маршрутизатора виртуальный MAC-адрес и VIP присваиваются одному из резервных устройств. Таким образом обеспечивается непрерывный доступ узлов к шлюзу даже в случае отказа одного из устройств в рамках виртуального маршрутизатора. kb.numaedge.ru
Приоритет влияет на процесс распределения ролей: маршрутизатор с большим приоритетом становится Master. Значение приоритета — целое число в интервале от 1 до 255. spw.ru
•	Настройка
Узлы в сети настраиваются так, чтобы направлять пакеты на VIP-адрес виртуального маршрутизатора, вместо IP-адресов физических интерфейсов.
Главное и резервное устройства периодически отправляют объявления VRRP для поддержания своей доступности. Эти объявления включают информацию о состоянии группы VRRP, такую как приоритет устройства и IP-адрес.
Резервное устройство отслеживает состояние главного устройства, получая объявления VRRP. Если резервное устройство не получает объявления от главного устройства в течение определённого времени, оно считает, что главное устройство неисправно, и запускает переключение.
 Сферы применения
Создание избыточных шлюзов по умолчанию — VRRP гарантирует, что сетевые устройства по-прежнему смогут получать доступ к внешним сетям, если основной маршрутизатор обнаружит неисправность.
Балансировка нагрузки — если создать несколько групп с разными VRID и VIP, VRRP позволяет равномерно распределить нагрузку.
 
•	Ограничения
IP-адрес на интерфейсе может быть задан только статически.  
Протокол не работает с интерфейсом многолучевого распространения по IP-сети (IPMP) — для VRRP требуются определённые MAC-адреса. 
Переключение с основного маршрутизатора на резервный занимает некоторое время, что приводит к безусловному разрыву установившихся соединений поэтому использование этой технологии может быть критично для работы сервисов IP телефонии или систем высокой достуности в реальном времени.

Некоторые преимущества использования VRRP в vESR:
Высокая доступность сети. VRRP предоставляет резервный маршрутизатор, который может заменить основной в случае сбоя. Это гарантирует, что сетевой трафик продолжит поступать даже при сбое.
Балансировка нагрузки. VRRP позволяет нескольким маршрутизаторам совместно использовать виртуальный IP-адрес. Это помогает распределить сетевой трафик между несколькими маршрутизаторами и повысить производительность сети.
Лёгкость настройки и обслуживания. VRRP не требует сложных протоколов маршрутизации или конфигураций.
Масштабируемость. VRRP поддерживает до 255 групп VRRP на подсеть и несколько виртуальных маршрутизаторов на физический маршрутизатор.

•	Настройки VRRP-кластера на Eltex VESR.
Методика настройки VRRP-кластера на маршрутизаторах Eltex VESR заключается в использовании механизма IP Failover для синхронизации состояний и обеспечения высокой доступности. Это более надежный и интегрированный способ, чем просто настройка VRRP на каждом интерфейсе в отдельности.
1: Базовая настройка интерфейсов и VRRP
Настройка идентична на обоих устройствах, кроме приоритетов VRRP.
На Устройстве 1 (Master):
! Настройка физических интерфейсов
interface gigabitethernet 1/0/1
  description "WAN"
  security-zone UNTRUST
  ip address 10.10.10.3/24
  vrrp id 2
  vrrp ip 10.10.10.2/24        ! Виртуальный шлюз для WAN
  vrrp priority 110            ! ВЫСОКИЙ приоритет на мастере
  vrrp group 1                 ! Важно: все интерфейсы в одной группе
  vrrp preempt delay 60
  vrrp
exit

interface gigabitethernet 1/0/2
  description "LAN"
  security-zone TRUST
  ip address 172.16.1.2/24
  vrrp id 1
  vrrp ip 172.16.1.1/24        ! Виртуальный шлюз для LAN
  vrrp priority 110            ! ВЫСОКИЙ приоритет на мастере
  vrrp group 1                 ! Та же группа, что и на WAN
  vrrp preempt delay 60
  vrrp
exit

! Специальный интерфейс для обмена служебным трафиком failover
interface gigabitethernet 1/0/3
  description "Failover_Link"
  security-zone TRUST
  ip address 192.168.30.1/30   ! Адрес на Устройстве 1
exit
На Устройстве 2 (Backup):
! Настройка ФИЗИЧЕСКИХ адресов и маски ДОЛЖНЫ отличаться
interface gigabitethernet 1/0/1
  description "WAN"
  security-zone UNTRUST
  ip address 10.10.10.4/24     ! Другой IP в той же сети
  vrrp id 2
  vrrp ip 10.10.10.2/24        ! Виртуальный шлюз ДОЛЖЕН быть одинаковым
  vrrp priority 100            ! НИЗКИЙ приоритет на резерве
  vrrp group 1
  vrrp preempt delay 60
  vrrp
exit

interface gigabitethernet 1/0/2
  description "LAN"
  security-zone TRUST
  ip address 172.16.1.3/24     ! Другой IP в той же сети
  vrrp id 1
  vrrp ip 172.16.1.1/24        ! Виртуальный шлюз ДОЛЖЕН быть одинаковым
  vrrp priority 100            ! НИЗКИЙ приоритет на резерве
  vrrp group 1
  vrrp preempt delay 60
  vrrp
exit

interface gigabitethernet 1/0/3
  description "Failover_Link"
  security-zone TRUST
  ip address 192.168.30.2/30   ! Адрес на Устройстве 2 в той же подсети
exit
2: Настройка IP Failover
Это ключевой компонент для синхронизации состояний сессий (NAT, IPsec, DHCP) между узлами. Конфигурация должна быть зеркальной на обоих устройствах, кроме роли (role).
На Устройстве 1 (Primary):

ip failover
  local-address 192.168.30.1    ! Адрес этого устройства на линке failover
  remote-address 192.168.30.2   ! Адрес соседа на линке failover
  vrrp-group 1                  ! Группа VRRP, состояния которой нужно синхронизировать
  mode active-standby           ! Режим "Активный-Резервный"
  role primary                  ! Роль УЗЕЛА в кластере (Primary/Secondary)
  sync-type unicast             ! Тип синхронизации
  port 3333                     ! UDP-порт для синхронизации
  enable
exit
На Устройстве 2 (Secondary):
ip failover
  local-address 192.168.30.2
  remote-address 192.168.30.1
  vrrp-group 1
  mode active-standby
  role secondary               ! Здесь роль Secondary
  sync-type unicast
  port 3333
  enable
exit
3: Настройка синхронизации состояний файрвола
Это критически важно для бесперебойной работы при failover.
ip firewall failover
  sync-type unicast
  port 3333                    ! Должен совпадать с портом в 'ip failover'
  enable
exit
4: Настройка политик безопасности
Разрешите обмен служебным трафиком между узлами.
security zone-pair TRUST self
  rule 66
    action permit
    match protocol vrrp        ! Разрешить VRRP
    enable
  exit
  rule 67
    action permit
    match protocol udp
    match destination-port 3333 ! Разрешить трафик синхронизации состояний
    enable
  exit
exit

•	Ключевые принципы при настройке:
•	Использование VRRP Group: Объединение интерфейсов в группу (vrrp group 1) гарантирует их согласованное переключение.
•	Отдельный физический линк для Failover: Настоятельно рекомендуется использовать выделенный интерфейс (как gi1/0/3 между Master и Backup на схеме Рисунок 15-1 в примере) для синхронизации состояний. Это повышает надежность и не загружает полезный трафик.
•	Синхронизация состояний: Механизм ip failover синхронизирует не только таблицы сессий (NAT, IPsec), но и, при использовании ip firewall failover, состояния правил межсетевого экрана.
•	Зеркальность конфигурации: Конфигурация на обоих узлах должна быть практически идентичной, за исключением:
Физических IP-адресов интерфейсов.
•	Приоритетов VRRP (priority).
•	Роли в IP Failover (role primary / role secondary).

•	Расшифровка настроек таймеров VRRP на интерфейсе GigabitEthernet 1/0/1

Интервал отправки VRRP advertisement-сообщений: 1 сотая секунды (0.01 сек)
Стандартное значение: обычно 100 (1 секунда)

  ip ospf wait-interval 40
  ip ospf poll-interval 120

Расшифровка интервалов OSPF и их влияние на работу VRRP-кластера
Приведенные настройки OSPF действительно критически важны для времени сходимости и корректной работы в кластере VRRP. Вот расшифровка каждого параметра:
1. ip ospf hello-interval 10
Значение: 10 секунд
Описание: Интервал отправки OSPF Hello-пакетов
Влияние на переключение: Определяет, как часто маршрутизаторы обмениваются keepalive-сообщениями. Увеличение интервала уменьшает нагрузку на CPU, но замедляет обнаружение сбоев.
2. ip ospf retransmit-interval 5
Значение: 5 секунд
Описание: Интервал перед повторной передачей OSPF-пакетов
Влияние на переключение: Определяет, как быстро будут переотправляться потерянные пакеты. Меньшие значения ускоряют восстановление после потерь пакетов.
3. ip ospf dead-interval 40
Значение: 40 секунд
Описание: Время, после которого сосед считается недоступным
Влияние на переключение: Критически важный параметр. Определяет, как быстро OSPF обнаружит недоступность соседа. Соотношение dead/hello = 4:1 является стандартным, но для быстрого переключения в кластере рекомендуется уменьшить это значение.
4. ip ospf wait-interval 40
Значение: 40 секунд
Описание: Время ожидания перед выбором DR/BDR
Влияние на переключение: Влияет на время выбора designated router в multi-access сетях. Должен быть равен или немного больше dead-interval.
5. ip ospf poll-interval 120
Значение: 120 секунд
Описание: Интервал опроса для неактивных соседей
Влияние на переключение: Используется для опроса соседей, которые перестали отвечать. Не оказывает прямого влияния на скорость переключения.

Рекомендации для работы с VRRP-кластером
Для обеспечения быстрого переключения в кластере VRRP рекомендуется:
Уменьшить dead-interval и hello-interval:
ip ospf hello-interval 1
ip ospf dead-interval 3
Это позволит обнаружить сбой соседа в течение 3 секунд вместо 40.
Согласовать таймеры OSPF с VRRP:
VRRP таймеры (особенно advertise) должны быть настроены агрессивнее OSPF
OSPF должен обнаруживать сбои быстрее, чем происходит переключение VRRP
Использовать BFD для ускорения обнаружения сбоев:
Настроить более агрессивные VRRP-таймеры:
vrrp timers advertise 1  ; 0.01 секунды
Текущие настройки с dead-interval 40 секунд могут привести к задержке переключения до 40 секунд, что неприемлемо для VoIP и других чувствительных к задержкам сервисов. Рекомендуется уменьшить эти значения для обеспечения быстрой сходимости.
Чтобы OSPF быстро реагировал на изменения после переключения VRRP, нужно уменьшить его таймеры.

Вариант 1: Уменьшение Hello и Dead Intervals (Рекомендуется)
Это настраивается на всех интерфейсах, участвующих в OSPF, включая LAN и туннели.
interface gigabitethernet 1/0/2
  ip ospf dead-interval 2      ! Dead Interval в секундах
  ip ospf hello-interval 5   ! Hello Interval в секундах

tunnel vti 5
  ip ospf dead-interval 2
  ip ospf hello-interval 5

tunnel vti 6
  ip ospf dead-interval 2
  ip ospf hello-interval 5
Пояснение: Сосед OSPF будет считаться недостижимым, если в течение 2 секунд не придет hello-пакет. Hello-пакеты отправляются каждые 5 секунд.

Вариант 2: Fast Hello (Более агрессивный вариант)
Некоторые реализации позволяют использовать еще более быстрые таймеры.
interface gigabitethernet 1/0/2
  ip ospf dead-interval 1
  ip ospf hello-interval 1
Внимание: Слишком агрессивные таймеры могут создать нагрузку на CPU и привести к нестабильности из-за ложных срабатываний при временных задержках пакетов.
3. BFD (Bidirectional Forwarding Detection): 
Это самый современный и эффективный протокол для быстрого обнаружения сбоев на канальном уровне. Он работает независимо от OSPF и может использоваться для его ускорения.
Разрушить прохождение пакетов протокола на Мэжсетевом экране ( firewall) на всех маршрутизаторах:
security zone-pair UNTRUST self
  rule 20
    action permit
    match protocol udp
    match destination-port port-range 3784
    enable
  exit

Включите BFD на физическом линке между маршрутизаторами (gi1/0/3):

interface gigabitethernet 1/0/3
  description "VRRPlink"
  security-zone TRUST
  ip address 192.168.30.2/30
  ip bfd min-rx-interval 300
  ip bfd min-tx-interval 300
  ip bfd multiplier 3
exit 

Настройте OSPF на обоих маршрутизаторах  на использование BFD:

tunnel vti 5
  security-zone UNTRUST
  local address 10.10.10.2
  remote address 10.10.20.2
  ip address 192.168.100.1/24
  ip ospf bfd-enable
  ip ospf instance 1
  ip ospf priority 255
  ip ospf
  enable
exit

tunnel vti 6
  mtu 1400
  security-zone UNTRUST
  local address 10.10.10.2
  remote address 10.10.30.2
  ip address 192.168.200.1/24
  ip ospf bfd-enable
  ip ospf instance 1
  ip ospf priority 200
  ip ospf neighbor 10.10.30.2
  ip ospf
  ip tcp adjust-mss 1380
  enable
exit

Пояснение BFD:
interval 100: Интервал отправки BFD-пакетов (100 мс).
min_rx 100: Минимальный интервал, с которым устройство готово получать BFD-пакеты (100 мс).
multiplier 3: Сессия будет разорвана после пропуска 3-х пакетов.
Общее время обнаружения сбоя: 100 мс * 3 = 300 мс.
BFD берет на себя роль детектирования сбоя линка, а OSPF использует его сигнализацию для почти мгновенной реакции.
Настройте OSPF timers на hello-interval 500 и dead-interval 2 для баланса между скоростью и стабильностью.

Проверим работу vrrp кластера с такими значениями счетчиков таймеров OSPF и  включенным BFD на всех туннеля и маршрутизаторах ( таймеры VRRP остапвлены  в значениях по умолчанию):

tunnel vti 5
  security-zone UNTRUST
  local address 10.10.10.2
  remote address 10.10.20.2
  ip address 192.168.100.1/24
  ip ospf bfd-enable
  ip ospf instance 1
  ip ospf priority 255
  ip ospf hello-interval 1
  ip ospf retransmit-interval 2
  ip ospf dead-interval 2
  ip ospf wait-interval 2
  ip ospf
  enable
exit
tunnel vti 6
  mtu 1400
  security-zone UNTRUST
  local address 10.10.10.2
  remote address 10.10.30.2
  ip address 192.168.200.1/24
  ip ospf bfd-enable
  ip ospf instance 1
  ip ospf priority 200
  ip ospf hello-interval 1
  ip ospf retransmit-interval 2
  ip ospf dead-interval 2
  ip ospf wait-interval 2
  ip ospf neighbor 10.10.30.2
  ip ospf
